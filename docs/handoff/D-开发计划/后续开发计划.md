# 后续开发计划

> 状态：**仅规划**；实施状态列见 `任务清单.md`  
> 约束：Windows + Git + Python + VS Code + GitHub 私仓 + DeepSeek Harness；**暂无云服务器**；控成本  
> 更新：2026-11-02（Asia/Shanghai）

---

## 1. 本地环境准备计划（需 Arthur / DeepSeek）

1. 确认 Python 3.11+、`git --version`  
2. 私仓克隆；创建分支 `main` / `develop`  
3. `python -m venv .venv`；安装依赖（见下）  
4. 复制 `.env.example` → `.env`（API Key 不进 Git）  
5. 跑通 `pytest` 烟雾测试与 `make research-demo`（待实现）  
6. **不做**：未批准的付费云资源购买  

建议最小依赖：`httpx`, `pydantic`, `sqlalchemy`, `typer`, `rich`, `pymupdf`, `python-docx`, `openpyxl`, `trafilatura`（可删减）。

---

## 2. GitHub 项目结构（建议）

```
compute-dual-projects/          # 私仓根（名称可改）
  README.md
  docs/
    handoff/                    # 本交接包全文复制
  apps/
    api/                        # FastAPI 可选；前期可先 CLI
    worker/                     # 异步任务（可后置）
  packages/
    common/                     # LLM/工具抽象
    evidence/                   # 证据模型
    research/                   # 研究工作流
    matching/                   # 项目B匹配
  data/
    raw/.gitkeep
    private/.gitignore
  tests/
  scripts/
  pyproject.toml / requirements.txt
```

单体仓即可；A/B 用 `project_id` 区分，敏感目录权限靠文件系统 ACL + gitignore。

## 3. Python 后端结构

前期 **CLI 优先**（Typer），降低运维：

- `ak research start --project A --topic "..."`  
- `ak evidence add ...`  
- `ak match run --demand dem_001`  

后期可选 FastAPI：`/tickets`, `/evidence`, `/match`。  
鉴权：本地单用户 token 即可。

---

## 4. 数据库结构（初版）

**SQLite 起步 → 可迁 Postgres**

共享库 `research.db`：documents, evidence_claims, entities, edges, tickets, qa_reviews  
私密库 `biz_private.db`：contacts, quotes, demands, suppliers, matches, deal_logs, audit_exports  

关键索引：url hash、claim_id、project_id、epistemic_tag。

## 5. 搜索服务接口（草图）

```json
POST /tools/search { "query": "...", "limit": 10 }
→ { "hits": [{"title","url","snippet","rank"}], "provider","retrieved_at" }

POST /tools/fetch { "url": "..." }
→ { "status", "text", "content_type", "retrieved_at" }
```

实现可先包一层外部搜索；Harness 开发期也可用人工粘贴 URL 入队。

## 6. 研究工作流实现顺序

1. Ticket + Question 数据模型  
2. 手动添加 URL → fetch → evidence  
3. 半自动：search → 人工勾选 → fetch  
4. 抽取与报告模板  
5. QA 检查清单自动化  

对应项目A试研已人工走通「搜索→摘录→证据表→报告」，代码是把该路径产品化。
