4. 禁止把「仅规划 / 需本地」写成「已完成」。

## 2. 证据字段（对齐设计 §6）

逻辑表 `evidence_claims`：

| 字段 | 说明 |
|------|------|
| claim_id | 稳定主键；报告引用 `[@claim_id]` |
| project_id | `ak` / `outbound` / … |
| statement | 结论内容 |
| epistemic_tag | `fact` \| `inference` \| `hypothesis` \| `missing` |
| source_name, url, published_at | 来源；fact 必须可打开 url |
| retrieved_at_shanghai | 获取时间 Asia/Shanghai |
| excerpt | 原文摘录 |
| source_type, trust_level | 类型与可信度 |
| verification_status | `unverified` → `cross_checked` → `disputed` → `rejected` |
| conflict_notes, doc_id | 冲突说明；原始资料 id |

闸门：`fact` 无 url → 拒写。冲突禁止静默覆盖。

现行 Markdown 样板：`A-算力之王AK/证据表.md`（列名与上表同构）。

## 3. 公开库 vs 敏感库（L0–L3）

| 级别 | 内容 | 访问 | 落点示例 |
|------|------|------|----------|
| L0 公开研究 | 已发表摘要、公开产业 | A/B 研究角色 | compute-shared / A·B 公开区 |
| L1 内部研究 | 未发布证据与草稿 | 项目内 | 项目目录 / shared 草稿区 |
| L2 商务敏感 | 联系人、报价、合同、会员 PII | Arthur + 明示授权 | **B/99**；`compute-ak-private` |
| L3 密钥 | API Key | 仅本地环境变量 | 不进仓库 |

出海细则摘要：联系人/报价/合同/商务原文 → **仅 B/99**；`compute-outbound-private` 语义对齐、不另立规则；外发须 Arthur 确认。全文见 B《敏感数据目录与访问约定》与 `权限与目录摘要-v0.1.md`。

敏感商务原文默认不送第三方 LLM；或脱敏后送（《基础设施设计》§1）。

## 4. 智能体调用顺序与工具契约

对齐《基础设施设计》§9–10 ToolRouter（JSON schema 待本地实现）：

| 工具 | 输入 | 输出 | 备注 |
|------|------|------|------|
| search | query | hits[] | 必存 query/时间/URL；失败标 `search_failed` |
| fetch | url | text, status | 403 记状态码，换源，不编造 |
| parse_file | path | RawDocument | 文本块/页码/表/hash |
| evidence_add | claim | claim_id | 见 §2 |
| kb_upsert | entity | id | 公开→共享 KB；L2→隔离 |
| match_suppliers | demand | matches[] | **仅 B** |

**最小闭环顺序**

```
明确范围 → search → fetch → parse_file
  → evidence_add → 交叉验证 → kb_upsert
  → 评测 → 成稿/沉淀（挂 claim_id）
```

Orchestrator 建 ResearchTicket → 分解问题 → Search/Fetch/Extract → Analyst → Verifier → Writer。  
Grok 侧：群内派活 + SendToAgent；本地侧队列 **需本地**。

失败分类：`network` / `parse` / `policy_block` / `budget`；降级跳过该源、标记缺口。

## 5. 评测（对齐设计 §12）

自动：断链率、无摘录结论占比、epistemic 标签缺失率。  
人工：准确性、夸大、推断当事实；每篇至少抽 3 条。  
评分写入逻辑表 `qa_reviews`；不达标不得标「可对外」。
