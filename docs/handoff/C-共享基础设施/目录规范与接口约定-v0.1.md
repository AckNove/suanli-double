## 0. 目标与硬约束

**目标**：让双项目「研究工作流可跑通」——搜索 → 读页 → 证据 → 知识沉淀；AK 与出海对共享层同等重要。

**硬约束**

1. 控成本：不采购云、不产生费用；本期只交文档与本地文件夹约定。  
2. 研究知识可共享；客户/报价/会员/商务必须隔离（流程 + 路径；平台无系统 ACL）。  
3. 禁止编造来源与数据；事实 / 推断 / 假设必须分栏。  
4. 禁止把「仅规划」写成「已完成」。

### 1.1 共享 vs 项目仓

| 区域 | 路径 | 可写角色 | 内容 |
|------|------|----------|------|
| 运行时共享 | `compute-shared/` | 双项目公开级；基建维护模板 | 证据/知识/模板 |
| 交接约定 | `C-共享基础设施/` | 基建维护；总协调审定 | 设计与权限摘要（非业务仓） |
| A 公开 | `A-算力之王AK/` | AK、产业研究员、总协调 | 主文档、研究、证据表 |
| A 会员/付费 | `compute-ak-private/` | 仅 A + Arthur | 会员名单、付费正文 |
| B 公开 | `B/01`–`05` | 出海、总协调（指导） | 公开字段、脱敏跟进、市场 |
| B 敏感（规范） | `B/99-敏感商务_仅本项目/` | 出海 + Arthur；总协调默认不读原文 | 联系人、报价、合同、商务原文 |

**附注**  
`compute-infra/` = 约定工作副本，与 C/ 同步。出海敏感业务原文只写 **B/99**；`compute-outbound-private` 不另立第二套规则。Notion 镜像本期不建（等 Arthur）。

### 1.2 命名

- 证据 ID：`{项目前缀}-E{序号}`，如 `A-E01`（已有先例）。  
- 文件：`YYYYMMDD_` + 短 slug，或沿用已有模板名（`_模板.md`、`registry.csv`）。  
- 敏感文件建议名：见 B 已审定约定（`SUP-…_contacts.md`、`…_quote-YYYYMMDD.md`、`CONTRACT-…` 等）。  
- 公开侧对敏感内容只写指针：`见敏感仓：文件名`，不写具体值。

### 1.3 禁止混仓

- 禁止将 `99` 或会员/付费内容复制进 `C`、A 公开研究区、群聊、Notion 公开页、共享 memory。  
- 跨项目只传：市场结构、合规、公开竞品、已脱敏研究结论。  
- 外发商务：必须经 **Arthur** 确认（出海约定）。

## 2. 证据表字段（统一 schema）

以 `A-算力之王AK/证据表.md` 为现行样板；B 侧公开研究结论入库时**同构**（ID 前缀改 `B-E…`）。

| 字段 | 必填 | 说明 |
|------|------|------|
| ID | 是 | 稳定主键，报告内引用 |
| 结论内容 | 是 | 一句可核对的主张 |
| 事实/推断/假设 | 是 | 三选一；口播/成稿「事实」仅允许「事实」行 |
| 来源名称 | 是* | *假设可暂缺，但不得标成事实 |
| 原始链接 | 事实必填 | 可打开；禁止编造 URL |
| 发布时间 | 尽量 | 原文时间 |
| 获取时间 | 是 | Asia/Shanghai 日期 |
| 原文或数据摘录 | 是 | 短摘录，非改写冒充原文 |
| 来源类型 | 是 | 官网/公告/智库/媒体/转引等 |
| 可信度 | 是 | 高 / 中高 / 中 / 中低 / 低 |
| 核验状态 | 是 | 未核验 / 已对照 / 冲突 / 缺失 / 待核验 |
| 冲突信息 | 否 | 与何 ID 冲突、口径差 |

**写入闸门**：`事实` 行无原始链接 → 拒绝入表。推断须能指回所依据的证据 ID。

## 4. 智能体调用顺序（研究最小闭环）

适用于双项目公开研究任务（不含商务外发）。

```
1. 明确范围          项目负责人定 topic / 边界 / 不做清单
2. search.plan       产出 queries + must_sources + stop_rules
3. search.fetch      抓取；记录 url / title / fetched_at / hash
4. doc.parse         解析 PDF/页；保留 citations
5. evidence.write    按 §2 写入证据表；区分 事实|推断|假设
6. 交叉验证          冲突写入「冲突信息」；升级核验状态
7. knowledge.upsert  仅公开字段；敏感 → 对应 99/私域
8. eval.run          过评测清单（来源、分层、隔离、无编造）
9. 成稿 / 知识沉淀   结论挂证据 ID；失败则 log + 退回
```

**调度约定（无代码版）**

- 任务状态建议：`queued → running → blocked → done | rejected`  
- `blocked`：缺来源、抓取失败、isolation_violation、待 Arthur 确认外发  
- 日志字段（落本地 md/jsonl 即可）：`ts, level, module, project_id, task_id?, code?, message, context`  
- 失败语义：`retryable` vs `fatal`；403/超时可重试或换源；缺来源的 fact = fatal 拒写  

**逻辑接口名（契约形状，不绑定云）**  
`model.invoke` · `search.plan` · `search.fetch` · `doc.parse` · `evidence.write` · `knowledge.upsert` · `task.enqueue` · `eval.run` · `log.append`  
入参均带 `project_id` ∈ `{ak, outbound, infra, orch}`。细节字段见工作草稿 `/workspace/compute-infra/03-interface-conventions.md`（与本文冲突时以本文 + 后续《基础设施设计》为准）。
